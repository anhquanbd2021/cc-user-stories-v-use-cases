The eight checks

Delegating to an autonomous agent means someone — or something — resolves every ambiguity you leave behind. These are the eight questions a spec must answer so the agent doesn't have to guess:

  • 1. actor — who is this for, and under whose authority does the agent act?
  • 2. action — what does it do: a stated action or a numbered mainFlow?
  • 3. trigger — when does it start: a named event or schedule, never "as needed"?
  • 4. tool scope — which tools may it use: an explicit tools allowlist?
  • 5. done condition — how does it verify done: done or acceptanceCriteria the agent can check itself?
  • 6. failure modes — what can go wrong: failureModes or use-case extensions, each with a policy?
  • 7. escalation — when does it stop and ask: an escalation path?
  • 8. budget — how much may it spend: a budget cap on time, calls, or files?

The grades

  • agent-ready — 8/8. Every question answered; safe to delegate.
  • workflow-grade — 5–7/8. A real workflow, but guardrails are missing.
  • story-grade — 3–4/8. A delegable unit, but the agent still guesses.
  • vibe — 0–2/8. A wish, not a spec; the model fills the blanks.

Shapes: user story vs use case

The grader also detects the spec's shape. User story: actor + action + outcome — one trigger, one action, one verifiable outcome. Use case: mainFlow + extensions or failureModes — a multi-step workflow with named exception paths. Stories answer "is it done?"; use cases answer "what happens when it isn't done yet?".

Honest limits

This is structural linting. The grader verifies that each field exists and is plausible — it cannot judge whether your acceptance criteria are correct, whether the tool allowlist is tight enough, or whether the escalation path reaches a human who reads it. A spec can score 8/8 and still be a bad idea. Grading tells you the contract is written; it doesn't tell you the contract is wise.
